# 多模块依赖管理的规范


## 1. 规范目的

本规范用于约束 `Ai-Tester` 仓库后续新增的所有 Maven 子模块，确保：

1. 依赖版本统一管理。
2. 模块结构统一管理。
3. 构建方式统一管理。
4. 新增模块时接入成本最低，维护成本可控。

本规范是约束性规范。后续新增子模块时，默认必须遵循，除非有明确的架构例外说明。

## 2. 适用范围

本规范适用于当前仓库下所有由根工程聚合的 Maven 子模块，包括但不限于：

- 接口层模块
- 服务层模块
- Web 模块
- Demo 模块
- 公共工具模块
- 集成测试模块

父工程为根目录 [pom.xml](/E:/work/taichu/Ai-Tester/pom.xml)。

## 3. 总体原则

后续新增子模块必须遵循以下原则：

1. 父工程负责管理，子模块负责实现。
2. 版本统一放在父工程，子模块原则上不单独声明版本。
3. 子模块只声明本模块真正需要的依赖。
4. 父工程不承载业务代码，只做聚合和版本治理。
5. 所有子模块必须纳入父工程 `<modules>` 管理。
6. 所有子模块必须通过 `<parent>` 继承根工程。

## 4. 父工程规范

## 4.1 父工程角色

父工程必须承担以下职责：

- 作为聚合工程，统一构建全部子模块
- 作为版本治理入口，统一维护依赖版本
- 作为插件治理入口，统一维护插件版本
- 作为仓库配置入口，统一维护 `repositories` 和 `pluginRepositories`

## 4.2 父工程必须满足的要求

父工程必须满足以下要求：

1. `packaging` 必须是 `pom`
2. 必须包含 `<modules>`
3. 必须包含公共 `properties`
4. 必须使用 `dependencyManagement` 统一依赖版本
5. 建议使用 `pluginManagement` 统一插件版本

示例结构：

```xml
<project>
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.fuyue</groupId>
    <artifactId>Ai-Tester</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>pom</packaging>

    <modules>
        <module>demo1-sse</module>
    </modules>

    <properties>
        <java.version>21</java.version>
    </properties>

    <dependencyManagement>
        <dependencies>
        </dependencies>
    </dependencyManagement>
</project>
```

## 4.3 父工程禁止事项

父工程禁止出现以下情况：

1. 在父工程中直接编写业务代码
2. 在父工程 `dependencies` 中堆积大量通用依赖并强制子模块继承
3. 同一依赖在多个子模块中各自维护不同版本
4. 新增子模块但不加入父工程 `<modules>`

## 5. 子模块规范

## 5.1 子模块必须满足的要求

所有新增子模块必须满足以下要求：

1. 必须位于仓库根目录下一级目录
2. 必须拥有独立 `pom.xml`
3. 必须通过 `<parent>` 继承父工程
4. 必须拥有唯一 `artifactId`
5. 必须只声明本模块实际需要的依赖
6. 原则上不得在子模块中单独声明已由父工程管理的依赖版本

标准结构示意：

```text
Ai-Tester
├─ pom.xml
├─ demo1-sse
│  └─ pom.xml
├─ module-a
│  └─ pom.xml
└─ module-b
   └─ pom.xml
```

## 5.2 子模块 `pom.xml` 的最小模板

新增子模块时，`pom.xml` 至少应满足以下形式：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>com.fuyue</groupId>
        <artifactId>Ai-Tester</artifactId>
        <version>1.0-SNAPSHOT</version>
        <relativePath>../pom.xml</relativePath>
    </parent>

    <artifactId>module-name</artifactId>
    <name>module-name</name>
    <description>module description</description>

    <dependencies>
    </dependencies>
</project>
```

## 5.3 子模块命名规范

新增子模块命名应遵循以下规则：

1. `artifactId` 要与目录名保持一致
2. 使用小写英文和中划线
3. 名称必须表达模块职责

推荐示例：

- `demo1-sse`
- `ai-api`
- `ai-core`
- `ai-web`
- `ai-common`

不推荐示例：

- `module1`
- `test123`
- `newdemo`
- `temp`

## 6. 依赖管理规范

## 6.1 统一版本来源

所有公共依赖版本必须统一来源于父工程：

- 优先放在父工程 `dependencyManagement`
- 可通过父工程 `properties` 抽取版本号
- 子模块引用时原则上不写 `<version>`

正确示例：

父工程：

```xml
<properties>
    <spring-boot.version>3.2.5</spring-boot.version>
    <lombok.version>1.18.32</lombok.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>${spring-boot.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>

        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <version>${lombok.version}</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

子模块：

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
</dependency>
```

## 6.2 子模块依赖声明规则

子模块依赖声明必须遵守以下规则：

1. 只引入本模块直接使用到的依赖
2. 能复用父工程版本管理的，不再写 `<version>`
3. 测试依赖必须显式写 `scope=test`
4. 运行时依赖必须根据需要明确 `scope`
5. 可选依赖应显式标注 `optional=true`

## 6.3 允许单独写版本的例外场景

只有在以下场景中，子模块才允许单独声明版本：

1. 父工程暂未纳入该依赖的统一管理
2. 模块存在明确且合理的版本隔离需求
3. 升级验证阶段临时试点，但最终仍需回归父工程统一治理

出现例外时，必须同步补充到父工程治理方案中，不能长期分散管理。

## 6.4 严禁的依赖管理方式

严禁以下做法：

1. 同一个依赖在多个模块中各写一套版本
2. 在子模块中随意覆盖父工程已统一管理的版本
3. 将所有常用依赖直接塞进父工程 `dependencies`
4. 未经评估就引入重量级依赖

## 7. 插件管理规范

插件版本应尽量在父工程统一管理，推荐使用 `pluginManagement`：

```xml
<build>
    <pluginManagement>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.11.0</version>
                <configuration>
                    <source>${java.version}</source>
                    <target>${java.version}</target>
                </configuration>
            </plugin>
        </plugins>
    </pluginManagement>
</build>
```

子模块使用插件时：

1. 优先复用父工程统一配置
2. 仅在模块确有特殊需求时追加模块级配置
3. 不要在每个模块重复维护相同插件版本

## 8. 新增子模块的标准接入流程

后续新增子模块时，必须按以下流程执行。

## 8.1 第一步：创建子模块目录和基础工程

可以通过 Maven Archetype 创建，也可以手工创建。

PowerShell 示例：

```powershell
mvn archetype:generate -DgroupId=com.fuyue -DartifactId=new-module -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false
```

## 8.2 第二步：改造子模块 `pom.xml`

必须完成以下改造：

1. 增加 `<parent>`
2. 指向根工程 `Ai-Tester`
3. 去掉与父工程冲突的重复版本配置
4. 保留本模块自己的 `artifactId`、`name`、`description`

## 8.3 第三步：将子模块加入父工程

必须在根目录 [pom.xml](/E:/work/taichu/Ai-Tester/pom.xml) 的 `<modules>` 中加入：

```xml
<module>new-module</module>
```

未加入 `<modules>` 的模块，视为未正式接入。

## 8.4 第四步：补齐依赖治理

如果新增模块引入了新的公共依赖：

1. 先评估是否属于跨模块公共依赖
2. 如果是，优先提升到父工程 `dependencyManagement`
3. 如果只是本模块局部依赖，可以仅保留在本模块中

## 8.5 第五步：验证构建

新增模块后，至少要完成以下验证：

1. 在仓库根目录执行整仓构建
2. 验证父工程可以聚合构建该模块
3. 验证模块依赖版本没有冲突
4. 验证模块可以独立通过编译和测试

## 9. 新增子模块检查清单

每次新增子模块前后，必须对照以下清单检查：

1. 是否已创建独立目录和独立 `pom.xml`
2. 是否已继承父工程 `<parent>`
3. 是否已加入父工程 `<modules>`
4. 是否避免在子模块中重复声明公共依赖版本
5. 是否只引入了本模块真正需要的依赖
6. 是否复用了父工程统一插件配置
7. 是否完成整仓构建验证

## 10. 推荐模板

后续新增子模块时，可以直接按以下模板起步：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>com.fuyue</groupId>
        <artifactId>Ai-Tester</artifactId>
        <version>1.0-SNAPSHOT</version>
        <relativePath>../pom.xml</relativePath>
    </parent>

    <artifactId>new-module</artifactId>
    <name>new-module</name>
    <description>new module description</description>

    <dependencies>
        <!-- Only declare dependencies used directly by this module -->
    </dependencies>
</project>
```

## 11. 结论

后续所有新增子模块，都应按“父工程统一治理，子模块按需接入”的方式实现：

1. 先继承父工程
2. 再加入父工程聚合
3. 再按需声明依赖
4. 最后完成整仓验证

如果新增模块不遵循这套规范，短期可能能运行，长期一定会带来版本漂移、构建不一致和维护成本上升的问题。因此本规范应作为后续多模块扩展的默认执行标准。
